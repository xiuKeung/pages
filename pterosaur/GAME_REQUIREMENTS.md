# 《翼龙战车：遗迹战术》需求文档

## 1. 产品定位

以机械翼龙与黄色双炮战车为主角的**单人回合制战术解谜游戏**。玩家在小型遗迹棋盘中操控一组空地搭档，利用飞行、标记、炮击、对接和机关协作，在敌人行动前完成目标。

- 平台：现代桌面浏览器与手机浏览器。
- 表现：现有 3D 积木模型作为棋盘单位；视觉规范见 [ART_DIRECTION.md](ART_DIRECTION.md)。
- 时长：单关 3–8 分钟；首发 20 关。
- 核心体验：**看懂威胁 → 安排空地协作 → 解决局面 → 立刻复盘。**

## 2. 设计目标

1. 两个已有模型都必须有不可替代的玩法职责。
2. 每一回合的信息明确，失败能指出原因，避免靠反应速度或随机碰撞。
3. 适合触屏：点击单位、点击格子、点击行动，不要求双摇杆或连续飞行操控。
4. 20 关逐步教学并组合规则；后续可只增加关卡配置扩展内容。

## 3. 非目标

- 不做开放世界、实时射击、联网对战、抽卡、养成数值或付费系统。
- 不做自由拼装编辑器；“对接”是受规则约束的战术动作。
- 不复用旧版 `game.html` 的自动横向飞行规则，也不以“落到战车上回血”作为主要循环。
- 不要求真实军事模拟；炮击和敌方单位服务于积木遗迹解谜。

## 4. 核心循环

```text
读取本回合敌方预告
  → 让翼龙行动（越障 / 侦察 / 标记 / 操作高处机关）
  → 让战车行动（移动 / 炮击 / 推动 / 压力板）
  → 可选对接或发动组合技
  → 结束回合，敌方按预告执行
  → 达成目标、结算评价或进入下一回合
```

### 回合规则

- 每回合，机械翼龙与双炮战车各有 1 次行动。
- 玩家可自由决定行动先后；行动后可取消目标选择，但不可撤销已执行行动。
- 敌人下回合的目标格、攻击方向与机关影响范围必须在棋盘上预告。
- 结束回合后统一播放敌方移动、攻击、环境机关与状态结算。
- 关卡胜利条件可为抵达出口、恢复供电、回收物件、守住遗迹核心或击败关键单位。

## 5. 单位与能力

| 单位 | 基础行动 | 作用范围 | 核心职责 |
| --- | --- | --- | --- |
| 机械翼龙 | 飞行移动、标记、操作高处机关 | 可越过低墙与地面障碍；受空中封锁影响 | 侦察、取物、开路、制造炮击窗口 |
| 黄色双炮战车 | 地面移动、炮击、推动、压住压力板 | 受地面墙体与沟壑阻挡；可破坏指定障碍 | 清障、控制地面、保护目标、完成推进 |

### 协作规则

- **标记贯穿**：翼龙标记敌人或机关后，战车下一次炮击可穿过一段指定掩体，或获得额外效果。
- **相邻对接**：两个单位位于相邻格时可执行对接，恢复一格“核心稳定度”相关的防护状态，或为关卡提供一次组合技。
- **翼龙开路**：翼龙开启高处终端后，战车路线、桥梁或炮击角度发生变化。
- **战车护送**：战车停在指定区域才可让翼龙安全搬运大型能源，或阻挡地面威胁。

能力的最终格数、伤害、冷却和对接限制在原型阶段测试后确定；首版优先保持少量、稳定、可解释的规则。

## 6. 棋盘与敌人

### 棋盘

- 标准尺寸：`6 × 8` 或 `8 × 8`。
- 格子类型：普通地面、高台、断墙、可破坏障碍、压力板、供电口、出口、危险区。
- 所有格子都需以颜色外的方式表达状态，例如高度、纹理、描边、图标与文字提示。

### 敌人与机关

- **守卫炮台**：预告直线或扇形攻击，翼龙可标记 / 关闭，战车可摧毁 / 推离。
- **巡逻单位**：预告移动终点与接触伤害，主要用于阻塞路线。
- **扫描机关**：预告覆盖区域，要求翼龙绕飞或战车遮挡 / 断电。
- **环境机关**：桥、闸门、升降台和压力板；只在规则说明已出现后组合使用。

## 7. 核心稳定度与失败

- 使用 8 格“遗迹核心稳定度”取代传统生命条。
- 敌人攻击命中遗迹核心、关键供电设施或被护送目标时消耗稳定度。
- 主单位受击默认造成“受损”状态，而不是直接结束；受损会限制下一次行动，需对接、补给格或关卡特定机制解除。
- 稳定度归零时关卡失败，提供“重试本关”和“返回选关”。
- 原型阶段不加入随机暴击、命中率或不可预判伤害。

## 8. 关卡计划

| 关卡 | 新规则 | 目标示例 |
| --- | --- | --- |
| 1–2 | 选中、移动、敌方预告 | 抵达出口、避开一条炮线 |
| 3–4 | 翼龙越障与标记 | 取回高台能源，标记守卫 |
| 5–8 | 战车炮击与掩体 | 打开被墙阻挡的路线，推离巡逻单位 |
| 9–12 | 相邻对接与补给 | 先开终端，再保持两者协同推进 |
| 13–16 | 双目标与限回合 | 同时守住核心并回收能源 |
| 17–19 | 复合机关与多敌预告 | 管理多条攻击线与地形改变 |
| 20 | 遗迹核心战 | 分阶段机关、对接与最终撤离 |

每关提供：通关目标、可选三星条件、首次规则提示、重试入口和下一关入口。三星条件采用“完成目标 / 收齐探索积木 / 核心未受损”等可验证条件，不采用时间排行榜。

## 9. 交互与界面

### 桌面

- 鼠标点击单位后显示可行动格与能力范围；点击目标格确认。
- `Tab` 在翼龙与战车间切换；`Space` 结束回合；`Esc` 打开暂停菜单。
- 棋盘支持旋转、缩放与重置视角；操作时不得遮挡敌方预告。

### 手机

- 触控点击单位、格子和底部行动按钮；不使用双摇杆。
- 选中单位后，底部显示“移动 / 能力 / 对接 / 结束回合”四个主要操作。
- 默认斜侧俯视，双指缩放与单指拖动仅用于观察；不能与点击落子冲突。
- 竖屏优先：棋盘优先占据可视区域，状态信息压缩为单行 HUD。

### 必要 UI

- 当前回合、当前单位、剩余行动、关卡目标、核心稳定度。
- 敌方预告图例和可查看的“玩法说明”。
- 选关页显示 20 关进度与各关最高星级，保存于本机。
- 关卡结束显示完成原因、三星条件和重试 / 下一关。

## 10. 原型范围与验收

### 原型（先做 3 关）

1. **关卡 1：遗迹入口** — 教学移动、预告、结束回合。
2. **关卡 2：高墙能源** — 教学翼龙越障与拾取。
3. **关卡 3：标记炮线** — 教学翼龙标记和战车贯穿炮击。

原型验收标准：

- 两个 3D 模型均以棋盘单位形式出现，并有可辨识的移动 / 行动短动画。
- 玩家能在不阅读长文的情况下完成前三关；首次出现的新机制有一句话提示。
- 敌方攻击范围在玩家结束回合前可见，且实际执行与预告一致。
- 手机竖屏能完成三关：关键触控目标至少 44px，棋盘与操作不会互相遮挡。
- 无随机数决定关卡胜负；相同操作得到相同结果。

### 首发验收（20 关）

- 全部 20 关均可从新存档通关，规则按第 8 节递进。
- 每关至少要求翼龙和战车各完成一次有意义的职责，不能由单一单位独立解决。
- 每关在结束回合前都能读出威胁、目标和当前可行动作。
- 暂停、重试、切关、缩放、移动端触控和本地进度保存均可用。

## 11. 技术边界

- 在现有 `pterosaur/` 静态网页和本地 Three.js 依赖中实现，不新增服务端或账号体系。
- 尽量复用 `model.js`、`tank/model.js`、共享相机 / 展示台逻辑和现有本地资源。
- 关卡使用可读的 JavaScript / JSON 配置定义；规则逻辑与渲染分离，并为棋盘移动、预告、胜负和关卡递进编写测试。
- 游戏地址在原型确认后单独设置，不能覆盖已有 `game.html` 或 `rescue/`。
