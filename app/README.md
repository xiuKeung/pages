# 安家笔记 App 工程

本目录是“安家笔记”的 Capacitor 原生 App 工程。网页源码仍是唯一业务源码，位于本目录的上一级：

```text
Pages/
├── entrance/      工具入口
├── school/        深圳南山、福田学区查询
├── calculator/    房贷计算器
├── viewings/      看房记录
├── comparison/    房源对比
├── checklist/     购房清单
├── shared/        网页与 App 共用的运行时脚本
└── app/           本目录：iOS / Android 原生壳和构建工具
```

不要维护两套网页。日常先修改上一级网页目录并在浏览器验证；`cap:sync` 和打包脚本会把最新网页复制到原生工程。`app/www/`、Android 和 iOS 的 `public/` 资源均为构建产物，不应手改。

## 当前版本

本文功能说明对应 2026-10-28 的网页 **v2026.10.28.10**、App **1.1.23**（Android versionCode 25，iOS build 18）。后续发布应以 `../entrance/index.html`、`android/app/build.gradle` 和 `ios/App/App.xcodeproj/project.pbxproj` 中的版本为准。

## 看房记录功能

### 列表、搜索与操作

- 列表展示小区、楼栋 / 单元、房屋摘要、建成年份、报价、贷款年限和月供等信息，以及看房日期、精确到秒的最后编辑时间和关注等级。
- 显示用的“记录 N”是列表编号，不是底层持久 ID；删除记录后重新编号，图片等关联数据仍使用底层 ID。
- 支持关键词搜索、根据已有记录提供输入联想，以及重点关注、普通、已排除的复选筛选；记录数量随筛选更新。
- 记录分批显示，可点击“加载更多”；“更多信息”和“房源图片”折叠展示，缩短列表高度。
- 学校信息直接显示记录详情保存的小学、中学内容；某一项为空时显示“无数据”。
- 卡片操作顺序为：**查看 → 再记一套 → 查学区 → 算月供 → 复制信息 → 删除**。
- 小区名称旁可复制名称、打开地图；“查学区”带入小区名，“算月供”带入房源报价。
- “复制信息”按详情字段顺序生成文本并提示复制成功，不把图片文件复制到剪贴板。
- 删除记录需要确认，会删除该记录的文字数据及其图片；页面尽量保持在相邻记录的位置。

### 新增与详情编辑

新增和查看使用独立详情覆盖层，滚动限定在详情内，背景列表不参与操作。详情返回或“收起详情”回到列表，并恢复相应记录位置。新增房源的小区名为空时提供取消入口。

小区名称支持历史及官方小区数据联想。详情字段如下：

| 区域 | 字段和行为 |
| --- | --- |
| 小区 | 小区名称；支持复制、打开地图 |
| 现场快速记录顶部 | 小学、中学各占一整行；均可手动编辑、清空、复制、打开地图 |
| 快速记录第一组 | 楼栋 / 单元、总楼层；左右两列 |
| 快速记录第二组 | 面积、户型；左右两列 |
| 快速记录第三组 | 建成年份、梯户比；左右两列 |
| 快速记录第四组 | 报价、阳台朝向；左右两列，朝向带罗盘缩略图 |
| 房源图片 | 选择多张图片、拍照、缩略图列表 |
| 更多房源与贷款信息 | 看房日期、关注等级、物业公司、物业费、车位情况、车位费用、贷款年限、首付比例、商贷年利率；每次进入详情默认展开，也可收起 |
| 贷款估算 | 自动计算预计首付、贷款金额、等额本息月供和等额本金首月 / 末月月供 |
| 其他记录 | 房源链接、优点、缺点 / 风险、附近地标、个人备注 |

- 看房日期新建时默认为当天；建成年份选项上限为当前年份加 10 年，可记录新房未来建成年份。
- 总楼层、户型、贷款年限提供选择；贷款年限支持 1～40 年。
- 梯户比支持常用选项（包括 1 梯 3 户）及“其他”手动填写。
- 不单独保存“楼层”和旧“当前报价”业务字段；楼层可写进楼栋 / 单元，如 `1栋10A`，价格统一使用“报价”。
- 小区变化时可自动匹配学校；小学、中学均已有内容时不再次自动覆盖。匹配失败仍允许手填。
- 新增同小区房源时，可从最近的已有记录带入物业公司、物业费、建成年份、车位费用。
- 房源链接接受普通网址及小程序分享文字；详情右侧提供打开、复制操作。小程序分享文字不等同于浏览器可直接打开的网址。

### 自动保存与同小区再记一套

- 填写小区名称后，编辑内容自动保存；输入停止约 650 毫秒触发保存，并显示状态。
- 切后台或离页时会尝试提交待保存内容；系统强制终止进程、写入失败等情况不能保证最后一次输入一定落盘，应留意保存状态。
- 详情底部提供“同小区再记一套”：等待当前记录保存后，创建下一套房源。
- 列表“查看”右侧的“再记一套”直接基于选中记录创建新记录，不修改原记录。
- 带入字段：小区、物业公司、物业费、建成年份、车位情况、车位费用、小学、中学。
- 不复制房号、报价、面积、户型、朝向、图片、优缺点和备注；新记录采用新的 ID、当天看房日期及当前贷款默认值。

### 贷款默认值设置

“看房记录”标题右侧的“设置”打开默认值弹窗：

| 设置 | 初始值 | 可设置范围 |
| --- | --- | --- |
| 贷款年限 | 30 年 | 1～40 年 |
| 首付比例 | 30% | 0～100% |
| 商贷年利率 | 3.05% | 0～30% |

保存后仅用于后续新增房源及“再记一套”；已有记录、独立房贷计算器不变。每条记录仍可单独修改这些参数。默认值是设备本地偏好，保存在浏览器或 App WebView 的 `localStorage`，不包含在看房记录 ZIP 备份中；上述初始值只是录入默认值，不是实时银行报价。

### 阳台朝向与手动罗盘

- 字段名统一为“阳台朝向”，支持直接输入文字或用罗盘选择。
- 罗盘采用黑底刻度盘，顶部读数指示线固定；外圈刻度、方位字和北向标记一起旋转。
- 支持沿外圈拖动、点击刻度选择；电脑上可用方向键微调、Home 回到正北。
- **只保留手动选择**，没有自动实测、传感器权限申请、设备指南针调用或滑动条；原 Android/iOS 罗盘插件已删除。
- 正北、正东、正南、正西直接显示；其他方向按最近主方向描述，例如方位角 210° 为“南偏西30°”，240° 为“西偏南30°”。恰好 45° 时以南/北为主方向。
- 结果存入记录原有的 `orientation` 字段，由该文字还原角度并绘制缩略图；不额外保存一份罗盘图片。
- 旧记录文字保持不变；能够识别的旧八方位或带角度文字也可生成缩略图。空值或无法解析的自由文本不生成虚假的朝向图。
- 详情显示实际方向的缩略图，点击重新选择；对比页同时显示文字和缩略图，缩略图为 98px，点击可放大查看。

### 优缺点快捷标签

点击标签将文字追加到对应输入框，同一条标签不重复追加；输入框仍可自由编辑。

| 类型 | 当前标签 |
| --- | --- |
| 优点 | 采光好、安静、通风好、户型方正、视野开阔、交通方便、高赠送、高得房率、大阳台、南北通透、明厨明卫、人车分流、绿化好 |
| 缺点 / 风险 | 临街噪音、采光遮挡、装修旧、有渗水、户型不规则、停车困难、西晒、暗卫、对视严重、电梯等待久、人车混行、物业维护差 |

### 房源图片

- 可从设备选择多张图片，也可调用相机拍照；批量添加显示进度，每张处理完成后更新缩略图。
- 保存时生成用于列表和详情展示的缩略图；图片列表显示单张大小，标题显示图片总大小。
- 大图查看支持缩放、左右滑动和前后按钮切换；图片覆盖层位于返回按钮之上。
- 支持保存当前图片、保存本记录全部图片。App 通过原生相册能力保存，浏览器按浏览器支持的下载 / 分享能力处理。
- 删除单张图片需要二次确认；删除记录会清理该记录关联的图片数据。
- 图片保存在本机，不会自动上传服务器；需通过包含图片的 ZIP 备份分享或迁移。

### 房源对比

列表点击“对比房源”后选择记录，至少 2 条才允许“查看对比”；不限于 4 条。

- 对比小区、房号、看房日期、关注等级、链接、报价、面积、单价、户型、朝向、总楼层、建成年份、梯户比、物业与车位、地标、学校、贷款参数、两种月供、优缺点、备注及图片数量。
- 可只显示差异项。
- 各模块共用一张表，横向滚动时所有房源列一起移动；共用项目标题在滚动后固定，方便识别各列房源。
- 提供用户主动点击的横屏按钮；浏览器不允许主动旋转时提示手动横置设备。
- 朝向行带可点击放大的罗盘图，不需要进入原记录详情查看。

### 备份、共享与恢复

列表通过“备份”进入二级菜单，再选择导出或导入。

| 操作 | 行为 |
| --- | --- |
| 全量导出 | 导出全部看房记录及其图片到 ZIP |
| 选择记录导出 | 只导出勾选记录及其图片；选择列表显示小区、楼栋 / 单元、关注等级、看房日期 |
| 增量导入 | 保留本机记录，将导入内容作为新记录追加，重新生成关联 ID；不按原记录 ID 或最后编辑时间合并去重，重复导入会产生多份记录 |
| 覆盖导入 | 替换本机全部看房记录及图片；必须勾选确认框后才能确认执行 |

导入显示阶段与进度提示。看房记录备份仅处理看房记录及图片，不包含购房清单、贷款方案、学区收藏、官方学区数据或新增房源默认值。浏览器与 App 使用兼容备份格式；跨设备共享靠手动导出 / 导入，不是自动同步。

## 最常用命令

在 `app` 目录执行：

```bash
# 生成 Android 调试 APK（推荐的日常打包命令）
./generate-apk.sh

# 只同步网页源码到 Android / iOS 原生工程，不生成 APK
./build-app.sh sync

# 将当前 APK 通过同一 Wi-Fi 的二维码/链接分享给手机
./share-apk.sh
```

`generate-apk.sh` 的完整流程是：

```text
上级网页源码 → app/www → Capacitor 同步 Android / iOS → Gradle 生成 APK
```

Gradle 原始 APK 输出位置：

```text
app/android/app/build/outputs/apk/debug/app-debug.apk
```

`generate-apk.sh` 还会将该文件复制到项目根目录，便于直接安装和发送：

```text
Pages/安家笔记-debug.apk
```

项目根目录的 `安家笔记-debug.apk` 作为可下载的安装包提交到 GitHub；Gradle 构建目录中的原始 APK 不提交 Git。`share-apk.sh` 保持运行期间，同一个二维码会一直指向原始 Gradle 输出；每次重新打包后再次扫码下载即可获得最新 APK。若 Mac 更换 Wi-Fi、IP 变化或脚本重启，需要重新扫码。

## 脚本说明

| 文件 | 用途 |
| --- | --- |
| `generate-apk.sh` | 一键调用 `build-app.sh android-debug`，同步网页并生成调试 APK，再复制为项目根目录的 `安家笔记-debug.apk`。 |
| `build-app.sh` | App 的统一入口：`sync`、`open-ios`、`open-android`、`android-debug`。执行 `./build-app.sh help` 查看说明。 |

| `scripts/build-web.mjs` | 将网页页面复制到 `www/`，并打包 App 所需的共享脚本。通常由打包脚本自动调用，不需单独运行。 |

关键文件：

| 文件 | 用途 |

桌面图标和启动图是两套资源：桌面图标要考虑 Android 系统遮罩的安全边距；启动图使用独立资源，避免被桌面图标规则裁切或放大。

新增图标遵循 [ICON_STYLE.md](assets/ICON_STYLE.md)：以原 App 图标为参照，统一暖色黏土材质、配色、光照和构图。[ICON_PROMPTS.md](assets/ICON_PROMPTS.md)保存本次四个入口图标的完整生成提示词；首页已采用这套图标，网页与 App 共用；[预览页](../entrance/icon-preview.html)可并排查看。高分辨率原图保存在 `assets/entry-icons-clay-v1/`，页面使用 `../entrance/icons/clay-v1/` 中的 256px PNG。

## 本地数据与备份

- 原生 App 的看房记录保存于 SQLite；看房照片保存于 App 私有目录，SQLite 保存照片元数据和文件路径。新增房源的贷款默认值作为偏好保存在 WebView 的 localStorage。
- 浏览器版的看房记录文字保存在 localStorage，图片保存在 IndexedDB；清除对应站点数据会删除本地数据。
- 卸载 App 会删除这些私有数据。
- 看房记录的导出会生成 ZIP（JSON 数据和图片）；导入 ZIP 可恢复。
- Android 导出通过系统文件选择器让用户选择保存位置；iOS 使用系统分享/文件流程。
- 不包含账号、服务器或跨设备同步。

详细数据设计见 [native-app-migration.md](docs/native-app-migration.md)。

## 新电脑继续开发

先准备：Node.js、JDK 21、Android Studio 和 Android SDK；如果需要 iOS，再安装 Xcode。不要提交本机 SDK 路径或构建目录；需要分享的 APK 统一复制到项目根目录的 `安家笔记-debug.apk` 后提交。

当前 `build-app.sh` 使用 Homebrew 的 JDK 21 路径：

```text
/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home
```

因此 Apple 芯片 Mac 可通过 Homebrew 安装 `openjdk@21`。若新电脑的 JDK 21 安装在其他位置，先修改 `build-app.sh` 中的 `jdk21_home`，再打包。

```bash
git clone <仓库地址>
cd Pages/app
npm ci

# 生成 APK
./generate-apk.sh
```

如需打开原生工程：

```bash
./build-app.sh open-android
./build-app.sh open-ios
```

新电脑的 Android SDK 路径会自动写入本机 `android/local.properties`；该文件被 Git 忽略。

## Git 提交边界

应提交：网页源码、`app/src/`、`app/assets/`、脚本、`package.json`、`package-lock.json`、Android/iOS 原生工程配置和原生资源。

不提交：`node_modules/`、`www/`、`dist/`、Android/iOS 构建目录、`local.properties`、`Pods/`、`.DS_Store`、构建生成的 APK/AAB。例外：项目根目录的 `安家笔记-debug.apk` 保留 Git 跟踪并上传到 GitHub，供下载安装。

打包完成后，建议检查：

```bash
git status
```

确保新增的源码、图片和原生资源已被加入提交；忽略项可以在新电脑通过安装依赖和执行构建脚本重新生成。
